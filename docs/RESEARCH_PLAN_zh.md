# 从全身动作到环境：研究与实验设计

日期：2026-09-15。依据用户设计稿、当前官方资料，以及本机已经完成的第一轮实验。本文区分已测事实与下一阶段拟议实验。

## 1. 研究问题与贡献边界

你的核心直觉值得保留：身体朝向、肩髋旋转、收臂与抬脚会改变人体/机器人的空间占据，所以动作可能为合理的环境约束提供信息。

建议研究问题为：

> 在根部路径不能充分区分动作的情况下，身体部位的运动能否提供额外环境约束，并通过可执行的反事实验证产生有用的导航训练数据？

“动作后补场景”已有直接先例。[LfH-CP](https://arxiv.org/abs/2509.26513) 从关键时空配置生成动态障碍；[SUMMON](https://arxiv.org/abs/2301.01424) 根据人体动作合成场景；[SceneBot](https://arxiv.org/abs/2606.27581) 已明确提出从重定向动作做 hindsight scene reconstruction 并进行接触提示的全身 tracking。因此不能把“第一次 motion → scene”或“加一个 motion tokenizer”作为已成立的创新主张。

可检验的候选贡献是：**保留身体约束的表示 + 可执行替代动作的功能验证 + 独立场景中的闭环学习收益**。这是研究定位，尚未证明是完整文献空白，也没有被本轮几何实验验证。

给定动作 τ 与末端目标 g，生成的是 `p(S | τ,g)` 的候选场景集合。一条动作不能唯一还原原环境；motion 是示范轨迹，不是能应对环境变化的 policy。系统必须允许空场景、多个场景和拒绝生成。

## 2. 第一轮实验已改变的判断

已处理 900 条本地 G1 动作，并完成码本、场景评分器和模型碰撞几何复核。详见 [实验结果](RESULTS_zh.md)。当前证据表明：

1. 简单 RVQ 比固定关节姿态保留更多信息，但碰撞判断翻转仍达到 5.41%，不足以替代连续几何。
2. 小模型能提高有效场景候选的查询效率；当前 token 输入没有稳定优于较强的 root 信息基线。
3. 粗包围球严重高估固定姿态对照的碰撞：26 个候选见证仅 3 个在模型几何下保留，来自 2 条动作。
4. 位移筛选会接收篮球、跳跃等片段。它识别“有移动”，不能识别“适合平地导航”，更不能证明动作当时在避障。

因此下一阶段先改进功能验证与动作筛选，随后再判断是否值得扩大 tokenizer 或语言模型。

## 3. 系统设计

```text
源动作 + 来源/人物/镜像映射
  → 固定机器人模型，重定向和时间对齐
  → 原动作在空场景中的执行资格
  → motion codes + 重叠事件 + 连续身体几何
  → 小提案器：对象类型、事件、位置/尺寸分布
  → 全时段模型碰撞验证、几何细化
  → 可执行替代动作 + 障碍移除/放宽试验
  → 实际控制 rollout 和新场景观测
  → 高层目标导航策略
```

每个导出样本存储：源文件/片段/人物分组、机器人与几何哈希、坐标变换、token/事件、场景盒体或资产、原动作与替代动作、执行记录、观测来源、资格状态及拒绝理由。场景先在机器人坐标/尺寸下构造，不能在人体上验证后默认 G1 也能通过。

## 4. 下一步最有区分力的实验

### E1：先建立真实的全身功能见证

**问题：** 障碍是否真的让侧身、收臂、低头、抬脚变得必要或明显更有利？

从现有 900 G1、512 BONES-SEED G1 与带标签的人体源中，先检索每类约 20 对候选。这个数量是可操作的初始工作量，不是功效分析给出的充分样本量。先检查持续时间、身体朝向、地面接触、滑步、关节限制和跟踪质量。无障碍场景的原动作与替代动作都必须能执行。

匹配 root xy、速度、root z、root 朝向和目标，保留需要检验的身体差异。对于收臂应匹配根部和腿部；对于跨步要匹配推进过程，不能把完全不同的腾空跳跃当作普通步行对照。检索不足时使用受约束轨迹优化或动作编辑，并重新执行验证。

每一对动作做四格比较：

| 条件 | 原动作 | 可执行替代动作 |
| --- | --- | --- |
| 生成障碍存在 | 应完成且无非预期碰撞 | 在相同任务定义下受阻、碰撞或代价更高 |
| 障碍移除/放宽 | 应能执行 | 应恢复可行或优势差缩小 |

用 `W(替代动作) \ Dilate(W(原动作),m)` 提供候选搜索区域，最终仍由整个窗口的模型碰撞与 achieved rollout 检验。安全余量 m 由跟踪偏差及模型误差在独立标定数据上的分布确定，不固定凭直觉为 3 cm。

本轮三个模型几何见证仅用于调试，因为固定姿态的腿不迈步，物理可执行性未知；不能升格为 E1 数据。特别需要防止“一个脚本编辑出来的坏动作撞了东西”成为方法成功标准。

### E2：全身表示与 tokenizer 的有效信息

**比较输入：**

- root 路径、速度、高度、完整朝向 + 刚体碰撞包络；
- 完整连续关节/表面轨迹；
- 通用神经 VQ / RVQ；
- 身体部位或姿态/速度分流码本；
- token + 事件 + 连续几何。

后两者有额外信息或码率时如实计入资源表。连续几何旁路能够复现几何检查是设计事实，不可当作等信息预算下的学习增益。各表示使用相同训练来源分组与优化预算，在独立固定障碍探针上测 MPJPE、关键表面间距误差、接触/脚滑误差、碰撞翻转、false-safe 和码率。

最关键的子集是 **root 条件接近、身体部位不同的 E1 配对**。若改善只出现在 root 高度不同的蹲行动作，不足以证明额外关节信息的贡献。当前 pilot 的 root+token 排名未改善，不能据此断言所有神经 tokenizer 无用；它明确否定了“当前小码本自然就能帮忙”的假设。

### E3：小模型是否值得保留

比较同预算随机提案、全身几何搜索、结构化事件提案器、token 提案器、语义/语言提案器。统一最终验证器、每次最多 1–3 个物体、提案查询次数、优化步数及允许尺寸。增加 full-body 连续输入的学习器作为强基线。

先训练提案器输出结构：解释的事件 ID、对象类型、位置/尺寸分布、原动作要避开的区域、替代动作要受限的区域及不确定度。可以共享事件编码器，配绕行、窄缝、低障碍、横梁等输出头。训练目标由 E1 的几何与执行标签产生，不把生成器自己的语言判断当真值。

报告：有效场景/查询、拒绝率、功能见证率、独立场景多样性、对不同身体部位的覆盖、搜索耗时。消融：打乱事件顺序、遮蔽肩髋/脚信息、去掉功能目标、仅文本、去掉精确几何。只有在有意义的场景比例或查询成本上带来收益，才把语言模型写进核心贡献。

### E4：生成数据是否改善闭环导航

复用本机 `motion2scene-training` / SONIC 的 tracker 与观测/训练接口，首先固定并核验一个低层 checkpoint；阅读相应当前实验记录，避免混用旧 teacher 标签。已有项目的 tracking 或受辅助执行分数，不作为新研究的导航结果。

高层策略输入当前/历史的场景观测、机器人状态、目标，输出短时参考或 token。生成器允许看完整未来动作；测试策略不得收到未来示范、事件真值、原轨迹 ID 或可反推出正确动作的特权提示。重建场景后必须重渲染深度/视觉观测。

训练组：仅目标重标注；随机无碰撞配景；root-driven hindsight；全身且通过 E1 的 hindsight；scene-first 规划/示范基线。低层控制、训练量、策略容量和感知条件保持可比。

测试先独立采样场景、起终点和目标，再运行策略；不要只把另一批动作送进同一个场景生成器。设置未见过的窄缝宽度、梁高、障碍组合、起点偏移、感知误差。额外移除障碍或扩大通道，检查策略是否减少无用侧身/下蹲/绕路。

建议先用小型先导估计方差与失败模式，再冻结主实验规模。可将 5 个训练种子 × 500 个共同独立任务作为预算起点，依据最小有意义收益和场景聚类相关性决定是否足够。报告完成、碰撞、跌倒、超时、干预、身体部位碰撞及成功条件下的完成时间；以场景/源动作组为统计单位，比较配对差异及置信区间。

## 5. 数据泄漏和资格边界

按原始人物/表演/捕捉序列分组，再派生镜像、切窗、重采样、重定向、语言及场景版本。BABEL、HumanML3D、PHUMA 等可能共享源动作；按“数据集名字”划分不能防止泄漏。当前按来源目录的分组是探索性近似，仍需 metadata 验证跨目录重复与人物映射。

将样本状态明确分开：`geometry_candidate` → `model_geometry_checked` → `motion_execution_checked` → `functional_counterfactual_checked` → `policy_training_sample`。每个转换保留全部失败与分母。训练/测试资格不会由漂亮渲染、码本低误差或场景评分器高分自动获得。

## 6. 最先推进的具体工作

1. 用本轮误差最大的身体部位与 26→3 的失效案例校准几何提案；将模型碰撞查询引入候选细化阶段。
2. 优先整理收臂与侧身的匹配动作，因为它们更可能在相近 root 条件下体现额外身体信息。若数据不足，记录缺口并接入 BONES-SEED 时间标签。
3. 核验原动作/替代动作在空场景中的可执行性，构造首批 E1 四格证据；通过后再训练功能场景提案器。
4. 在 E1 有效动作对上重做 tokenizer 比较，再决定是否扩充神经架构和语言对齐。

当前合理结论是：本地数据和软件链路已经能开展研究，但“全身动作能额外带来多少**可执行**环境约束”仍是应优先回答的问题。
