# 小 LLM 首轮结果：JSON 合法不等于任务与动作信息保持

2026-09-18。[协议](LLM_INTERFACE_PROTOCOL_zh.md)在推理前固定了 12 个合成输入、两条路线、模型 revision 和预算。**所有 24 次生成完成；没有微调、真实 motion 验证或物理执行。** 原始日志本地保留，不用改 prompt 重跑来替换失败。

## 主要结果

| 条件 | JSON 合法 | 选择正确 | task 完整保持 | 所选 motion 完整保持 | 全接口通过 |
| --- | --- | --- | --- | --- | --- |
| 无 LLM 规则 + relay | 12/12 | 12/12 | 12/12 | 12/12 | 12/12 |
| Qwen3-0.6B + relay | 12/12 | 2/12 | 0/12 | 0/12 | **0/12** |
| 无 LLM 规则 + sidecar | 12/12 | 12/12 | 12/12* | 12/12* | 12/12 |
| Qwen3-0.6B + sidecar | 12/12 | 2/12 | 12/12* | 12/12* | **2/12** |

\* Sidecar 的保持由确定性程序提供，是保留**被选择记录**，不表示选对，也不是 LLM 复制成功。两条模型路线都未达到功能门槛。12 输入只有六种手写状态，每种两个扰动版本；不是 12 个独立物理任务，不计算泛化置信区间。

## 具体失败及其含义

Relay 的一个真实输出是：

```json
{"motion_id":"m17","task":"pass_the_beam","motion":null}
```

它的 JSON 合法，但把 task 的完整目标/坐标/停止/保持要求替换成一句文本，且丢失所选 motion。另一个 ID/顺序版本输出部分 motion 字段，仍有遗漏。全体 relay 的 task 均不完整。

Sidecar 在所有六种状态的两个版本都选择 hold：只有本来就应保持的两个输入通过，几何未知和不支持来态也没有返回 null。精确数字没有损坏，但行为选择错了。Relay 在原顺序版本始终选择 crouch，反序/重编号/改写版本始终选择 hold；每个版本都选 catalog 第一项。它仅在身体未离开的原版本与静止后的改写版本选对。这与候选位置偏置相容，但多个扰动同时变化，尚不能单独归因于顺序。因此，此提示下模型对关键状态改变没有产生正确响应。

所有生成都遇到 EOS，没有用尽 384 token 上限；不能把这里的字段损失归因于达到输出长度上限。模型非思考、greedy；未用约束解码、few-shot 或微调。本轮不能证明 0.6B 所有提示都失败，也不能推出所有小模型不适合。它发现的是**这条冻结接口配置**不足以承担语义选择与完整记录传递。

## 对下一步的影响

1. 保留 deterministic task/运动记录与校验，不要求 LLM 重写精确轨迹。禁止仅以 JSON 成功率宣称兼容。
2. 将选择和字段传递分别计分。下一版先缩短候选描述、拆开任务解析/选择、增加 task 参数最小对照；与原版同集配对但明确是开发调试。不能用它作为未见测试集。
3. 再登记 Qwen3-1.7B 同家族对照与冻结新 holdout，区分容量和接口设计；本轮未运行 1.7B 或 SmolLM3。
4. 真实 motion 的 L1 编码/解码与 L2 同来态执行仍待做。当前结论只支持“信息保真和选择必须分别检验”，不支持 tokenizer、导航或语言控制收益。

优先级不变：主要物理研究仍是 continuous/Linear29 的完整任务支持与瓶颈矩阵。用小模型找接口失败值得做；不据此改成大规模 VLA 训练。
